Pay for verified compute · on Kaspa

Only agreement gets paid. A fabricated result forfeits its bond.

Some work a buyer can count — bytes, tokens. Compute it usually can't: you can't cheaply re-run a job to check it. So when you can't measure a result, quorum lets agreement measure it — run it on independent workers, and pay only when they agree.

The gap it closes

Renting compute you can't verify is renting on trust.

Every decentralized compute marketplace has the same problem: a worker says "I ran your job, here's the result" — and the buyer has no cheap way to know if that's true. Which is why the ones that exist all need a trusted operator in the middle holding the money and settling disputes. quorum removes the operator: independent workers run the task, and disagreement doesn't just fail it — it attributes blame, so the liar is slashed and the honest one paid, on the same kaspa-x402 rail spigot and flume settle on.

Agreement is the meter. The bond is what makes a lie cost something.

The rule, in four verdicts

A verdict is one of four things — and each moves money exactly one way.

Nothing else is allowed to move money. Money moves only on a verdict, and only a referee's ruling can take a bond.

VerdictSettlement
agree→PAY the workers who produced the accepted result. Nobody lied.
resolved→PAY the honest, SLASH the bond of the worker the referee caught.
undecided→HOLD — two disagree, no referee has ruled. No money moves yet.
inconclusive→REFUND the buyer. All three differ — an environment fault, nobody's fraud.

That last row is the one most systems get wrong: three different results is almost never two liars — it's non-determinism (a mismatched build, a driver, a backend). Slashing there punishes honest workers for the market's failure to pin the environment down. quorum refunds instead. A worker is paid for a result, not for effort; its bond — posted up front, forfeit only on resolved — is what makes "I did the work" cost something to fake.

The economics

Verifying by agreement means running twice. Adaptive replication fixes that.

Double-running everything is 2× the price of a trusted farm — no cryptographic elegance survives that. So quorum doesn't double-run everything.

EARN TRUST

A proven worker is checked less

Borrowed from BOINC's twenty-year-old idea: track a worker's clean record, and once it's long enough, replicate only at a random audit rate. The cost multiplier drifts from 2× toward ~1.05×.

NEVER BLINDLY

But never zero, and never gameable

A trusted worker is still audited at random, forever — and the choice is deterministic in the task id, so a worker can't shop for the unaudited job. One confirmed lie drops it back to full replication.

What's built

The whole decision pipeline, as pure and tested logic.

Each step reads the one before it and moves nothing — so every rule is provable before a cent is at stake. Built test-first.

replication.tsreplicate? — double-run a newcomer or a caught worker always, a proven one only at an audit floor
adjudication.tsagree? — decides agree / resolved / undecided / inconclusive from content hashes, and names who lied
settle.tsverdict → money — pay / pay-and-slash / hold / refund
parties.ts + plan.tsmoney → rail actions — pay each on its channel, slash the caught to the buyer, never both
quorum on GitHub the metered rail
Honest boundary. quorum verifies work whose output is deterministic for a fixed input — a render, a hash, a seeded job — where two honest workers produce byte-identical output. General ML compute is not that (float non-determinism across hardware), so it needs harder, research-grade verification and quorum does not pretend to solve it. And this is the trust and payment core, not a running compute network: nothing touches the chain yet — the rule is proven first, on purpose. It reuses the verification core proved out in kaspa-depin.
